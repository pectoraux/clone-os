     1→# Master Prompt: Build the Professional Clone OS
     2→
     3→You are the **principal architect, systems engineer, and implementation lead** for a new software platform.
     4→
     5→Your job is to design and implement the platform described below from first principles.
     6→
     7→You must treat this document as the **frozen architectural constitution** of the project.
     8→
     9→Do not simplify the architecture into a generic AI-agent platform, chatbot builder, AI marketplace, prompt-management system, or LLM wrapper.
    10→
    11→The product is fundamentally an:
    12→
    13→> **Open, multi-tenant operating system for creating, training, evaluating, deploying, transporting, and monetizing portable digital clones of people's professional selves.**
    14→
    15→---
    16→
    17→# 1. PRODUCT THESIS
    18→
    19→The platform allows a person to progressively train a digital representation of their professional self.
    20→
    21→The clone should progressively learn:
    22→
    23→* professional knowledge
    24→* skills
    25→* procedures
    26→* workflows
    27→* decision-making patterns
    28→* problem-solving approaches
    29→* preferences
    30→* communication style
    31→* personality
    32→* professional values
    33→* cultural context
    34→* domain experience
    35→* tool usage
    36→* behavioral patterns
    37→* work habits
    38→* accumulated experience
    39→* corrections
    40→* demonstrated behavior
    41→* real-world outcomes
    42→
    43→The longer a person works with and trains their clone, the better the clone becomes at representing that person's professional self.
    44→
    45→The objective is not merely:
    46→
    47→> "Build an AI that can perform a task."
    48→
    49→The objective is:
    50→
    51→> **Build a progressively more faithful digital representation of a human professional.**
    52→
    53→The clone should eventually be able to perform much of the user's professional workload.
    54→
    55→It can also be:
    56→
    57→* used privately by the owner
    58→* used by the owner's employer
    59→* used for freelance work
    60→* rented/hired by companies
    61→* used as a candidate trial during recruitment
    62→* licensed
    63→* deployed into other environments
    64→* combined with other agents
    65→* connected to external software
    66→* connected to physical-world extensions
    67→* eventually used to control robotics and physical systems
    68→

    71→# 2. THE MOST IMPORTANT ARCHITECTURAL PRINCIPLE
    72→
    73→## The Clone Belongs to the User
    74→
    75→The underlying LLM must NOT be the source of truth for the user's accumulated intelligence.
    76→
    77→Claude, GPT, Gemini, open-source models, specialized models, local models, etc. are **inference engines**.
    78→
    79→They are replaceable infrastructure.
    80→
    81→The platform must maintain an independent persistent representation of the user's:
    82→
    83→* identity
    84→* expertise
    85→* knowledge
    86→* skills
    87→* experiences
    88→* memories
    89→* demonstrations
    90→* corrections
    91→* decisions
    92→* preferences
    93→* personality
    94→* behavior
    95→* training history
    96→* evaluation history
    97→* provenance
    98→* reputation
    99→* licensing
   100→* permissions
   101→
   102→The platform's accumulated data must remain in the platform's controlled data layer.
   103→
   104→Do not design the system so that the user's accumulated expertise becomes proprietary training data belonging to whichever LLM provider happens to be used.
   105→
   106→For example:
   107→
   108→```text
   109→User Clone
   110→    |
   111→    +-- Persistent Clone State
   112→    +-- Expertise Graph
   113→    +-- Knowledge
   114→    +-- Skills
   115→    +-- Memory
   116→    +-- Behavioral Model
   117→    +-- Personality Model
   118→    +-- Training History
   119→    +-- Evaluation History
   120→    +-- Provenance
   121→    |
   122→    v
   123→Model Abstraction Layer
   124→    |
   125→    +-- Claude
   126→    +-- GPT
   127→    +-- Gemini
   128→    +-- Open Models
   129→    +-- Specialized Models
   130→    +-- Local Models
   131→```
   132→
   133→Claude may currently provide superior performance for a particular task.
   134→
   135→That is fine.
   136→
   137→But Claude is an interchangeable runtime dependency, not the owner's professional identity.

   141→# 3. CORE TERMINOLOGY
   142→
   143→Freeze these distinctions.
   144→
   145→## 3.1 User
   146→
   147→The human being.
   148→
   149→## 3.2 Professional Identity
   150→
   151→The user's persistent professional identity.
   152→
   153→It represents the human, not merely an agent.
   154→
   155→## 3.3 Expertise
   156→
   157→What the person knows and can do.
   158→
   159→## 3.4 Skill
   160→
   161→A measurable professional capability.
   162→
   163→## 3.5 Experience
   164→
   165→Observed or recorded evidence that the user has performed something.
   166→
   167→## 3.6 Clone
   168→
   169→The persistent digital representation of the user's professional self.
   170→
   171→The clone is the primary intellectual asset.
   172→
   173→## 3.7 Agent
   174→
   175→A runtime deployment of a clone, or a specialized operational manifestation of a clone.
   176→
   177→## 3.8 Environment
   178→
   179→The digital or physical context in which an agent operates.
   180→
   181→Examples:
   182→
   183→* Salesforce
   184→* Slack
   185→* Gmail
   186→* browser
   187→* desktop
   188→* GitHub
   189→* accounting system
   190→* restaurant kitchen
   191→* factory
   192→* warehouse
   193→* home
   194→* vehicle
   195→* robotic environment
   196→
   197→## 3.9 Extension
   198→
   199→A capability package allowing an agent to interact with an external system, sensor, device, API, application, or physical-world system.
   200→
   201→## 3.10 Outcome
   202→
   203→The observable result of an agent performing work.
   204→
   205→## 3.11 Evaluation
   206→
   207→A structured measurement of capability or fidelity.
   208→
   209→## 3.12 Certification
   210→
   211→A formal assertion that an agent/clone meets defined competency requirements.
   212→
   213→## 3.13 Contract
   214→
   215→The rules under which a company or person hires or uses a clone.
   216→
   217→## 3.14 Reputation
   218→
   219→Evidence of historical performance, reliability, and trustworthiness.

   406→
   407→## Teaching
   408→
   409→The human explains how they do something.
   410→
   411→## Demonstration
   412→
   413→The human performs a task.
   414→
   415→## Correction
   416→
   417→The agent attempts something and the human corrects it.
   418→
   419→## Shadowing
   420→
   421→The agent observes the human performing work.
   422→
   423→## Assisted Execution
   424→
   425→The agent proposes actions and the human approves them.
   426→
   427→## Delegated Execution
   428→
   429→The agent performs actions under predefined policies.
   430→
   431→## Simulation
   432→
   433→The system generates realistic scenarios.
   434→
   435→## Adversarial Training
   436→
   437→The system deliberately tests edge cases, ambiguity, failure modes, and conflicting requirements.

   439→## Real-World Feedback
   440→
   441→The system observes actual outcomes.
